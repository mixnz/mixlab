# Translations

Every user-visible string goes through `t()`. No literal English in JSX.

```tsx
const { t } = useTranslation();
<button title={t("app.closeTab")}>{t("common.save")}</button>
```

## Where a string lives

The dictionary is split by owner and merged back in
[src/i18n/dicts.ts](../../../apps/desktop/src/i18n/dicts.ts):

- `src/i18n/{en,vi}.ts` — what no module owns: `common`, `app`, `settings`, `update`, `pagination`,
  `select`, `errorBanner`, and the part of `error` the shared layers raise.
- `src/modules/<id>/i18n/{en,vi}.ts` — that module's groups, and the part of `error` it raises.

**Groups stay flat at the top level**, which is what makes the split invisible: `t("connection.host")`
resolves through the merged object exactly as it did through one file.

Two rules the merge depends on, both with real teeth:

- **A module's dictionary imports nothing from `src/i18n/`.** `dicts.ts` imports the module's, so
  anything imported back the other way closes the circle — and the failure is `undefined` at
  runtime, not a compile error.
- **No group name may appear in two dictionaries**, except `error`, which is merged by hand because
  both sides genuinely contribute to it. A repeated group would be silently replaced by the later
  spread, taking every key of it. `dicts.ts` ends with a `Collision` type that makes this a
  compile error instead.

## Rules

- The English half is the source of truth for its own key set: `TranslationKey` is derived from the
  merged dictionary as dotted paths, so a key missing from `en` is a type error at the call site.
  Each `vi.ts` is annotated against its English counterpart (`SharedDict`, `DbDict`), so a key
  missing there is a type error in `vi.ts` itself. Add to **both** files.
- Group keys by area: `common.*` for words reused everywhere, then one namespace per feature
  (`app.*`, `connection.*`, `mysql.*`, `sqlTable.*`, `redis.*`, …).
- Interpolation is `{{name}}`, filled by the second argument:
  `t("connection.connectedStatus", { id })`. An unmatched placeholder is left as-is.
- An unknown key resolves to the key string itself rather than throwing — so a missing translation
  shows up as visible junk in the UI, not a crash.

## Errors from the backend

A rejected `invoke` carries an `AppError` — `{ code, params, cause? }` — not a message. Never
render it directly; put it through `errorMessage` from [src/core/errors.ts](../../../apps/desktop/src/core/errors.ts):

```tsx
try { await mysqlDropTable(id, db, table); }
catch (e) { onError(errorMessage(t, e)); }
```

`code` is a key under `error.*`, so adding a backend error means adding its key like any other
string — to the module's dictionary when the `err!` is inside `src-tauri/src/modules/`, and to the
shared one when it is in `ssh/`, `secrets.rs` or the webview itself. A key both layers raise goes in
the shared one. What a driver said travels as the `message` parameter and stays in
the server's own words.
- Non-ASCII characters are written as escapes in the dictionaries (`"✓ Tunnel OK"`).

## Language selection

`I18nProvider` wraps the app in `main.tsx`. The choice persists in `localStorage` under
`mixlab-lang`, defaulting to `en`. `useTranslation()` throws outside the provider.
